# Wyckoff 云端会员化改造方案（第二版）

2026-10-29 · 用户已确定：国内优先，海外支持信用卡；暂无收款商户；当前交付方案与开通指南，暂不实施登录、数据库、支付改造。股票切换残留标记与流式 Markdown bug 独立修复。

已采纳本轮反馈：F8 标注不按数量限额；F12 一次性全量迁到原生 Postgres；F4 修复 Markdown 标题/表格，并在目标产品中彻底删除扫描/推荐，改为用户主动浏览市场关注股票。市场功能与数据库改造本轮只更新方案，不修改现有功能入口。

## 目标与现状

把单人量价研究工具变为按账号保存、按功能与算力配额收费的在线工作台。保持图表、Wyckoff 语义标注、匿名回测、可审计交易回放的现有价值。套餐不承诺投资回报，不以推荐收益作为付费卖点。

本次检查的是当前工作区，包含原有未提交云端改造，不能据此断言线上已启用：

- React/Vite + Zustand 前端，Hono API；Better Auth 已配置邮箱密码登录，尚无 Google provider。
- Postgres 已保存身份与加密工作区。工作区实际是每用户一份 SQLite 序列化压缩加密快照，不是业务关系表全迁移。
- 快照未压缩上限 64 MiB；写请求锁整行；长任务可占用用户工作区锁；后台任务有约 240 秒预算。
- 现有 cron 只遍历最近活跃的最多 20 个账号，尚无套餐权限检查。此链路将在目标产品中完整删除。
- API Key 用户自带是当前产品入口；平台提供算力是新增能力，需要配额和成本控制。
- 无订单、订阅、权益、用量账本或支付 webhook。

证据：`apps/server/src/cloud/{auth,postgres,workspace,handler,cron}.ts`、`apps/server/src/db/schema.ts`、`apps/web/src/components/{AuthGate,KeySettingsPanel}.tsx`、`docs/vercel-deployment.md`。

## 方案比较与建议（尚未批准实施）

A. 推荐：保留 Better Auth 与 PostgreSQL，Google + 邮箱、所有业务表与会员账本一次性迁到原生 Postgres；国内直连微信/支付宝，海外用有资格开通的信用卡收单平台（优先评估 Stripe）。复用身份库和分析算法；一次切换成本更高，需完整迁移与回滚演练；需要维护多个支付适配器。

B. 合格境外商户统一走 Stripe，按账号资格启用微信/支付宝。代码少，但不能把“买家在中国”当成“大陆主体能开 Stripe”，也不能假定钱包自动续订普遍可用。当前无商户，因此不能直接选定此路径。

C. 更换整套身份与数据库平台。减少部分自管工作，但迁移身份、会话和所有权成本更高；当前已有 Better Auth/Postgres，没有足够理由更换身份服务；但业务持久层按用户要求全量重写为 Postgres。

基础设施建议先同区域部署 API 与数据库，候选为现有 Vercel+托管 Postgres 内测环境；面向国内正式用户前，对大陆移动/联通/电信网络实际测试登录、SSE、行情和支付回调。必要时换国内或邻近区域托管，域名、备案与跨境数据条件按最终部署和主体核验，不在这里断言已有条件满足。

平台 AI 使用受控模型档与每任务 token/工具调用上限；联网搜索计入预算。普通分析的最大 token 与工具轮次在成本基准测试后配置。首期不卖“无限 AI”，不自动扣费超额。BYOK 只替代模型费用，不绕过付费功能、服务器任务配额或并发限制。

组合任务扣费规则：普通分析与匿名回测分别只扣对应任务额度；回测决策点的内部 AI 调用不再扣普通分析次数，但受该任务的规模和成本上限限制。BYOK 使用相同功能与任务配额，只替代模型账单，不增加赠送次数。

配额周期：付费从权益生效时起按月周年计算（不足对应日期取当月最后一天），年付每月释放；Free 按 UTC 自然月。用量不结转。任务先原子预留额度，完成转消费，服务端失败释放；用户断线不会停止已入队任务，也不自动返额度。缓存重用不重复计费。用量明细可查。

成本验证：月收入减渠道费、模型+搜索、行情分摊、数据库/队列/带宽与退款准备；目标模型+搜索成本不超过实收收入的 25%，全部可变成本不超过 35%。这是预算目标。用平台日志测量 P50/P95 与满额用户成本，再发布最终套餐。示例单次成本仅供页面计算器演示，不是供应商报价。

## 登录体验与账号归属

沿用 Better Auth：新增 Google 按钮，保留邮箱入口给国内用户；邮箱上线前补齐验证与找回密码。前端展示免费套餐、升级入口、用量与到期时间。

Google OAuth 应用使用 Web application，配置同意屏幕、品牌、联系邮箱和域名；请求基本身份信息。回调为 `https://<正式域名>/api/auth/callback/google`，开发用 `http://localhost:5273/api/auth/callback/google`；`BETTER_AUTH_URL` 必须匹配。Client Secret 仅服务端保存。测试阶段明确测试用户，发布状态和验证要求以控制台为准。

Google 身份以 provider + account ID 绑定已有 user.id。已有邮箱账号关联必须验证所有权，不因客户端传入相同邮箱就合并；新增 Google 登录不转移工作区。登录/退出清理用户缓存、流和图表状态，服务端拒绝跨账号资源访问。

## 数据库目标：一次性全量原生 Postgres

遵照用户选择，一次性替换业务持久层；生产运行不保留 SQLite 快照适配或分用户双轨路径。保留 Better Auth 身份表和现有 user.id，算法引擎仍接收普通对象数组，不应依赖数据库类型。身份提供方无需重建。

全量关系表包括：instruments、klines/行情缓存索引、watch_groups/watch_items、sessions/messages、annotation_groups/annotations、backtest_runs/results、ai_backtest_runs/calls、runtime_settings、jobs，以及 billing_customers、orders、payment_events、subscriptions、entitlement_grants、usage_ledger。扫描/推荐相关表不迁入目标在线业务，旧快照只作离线备份保留。

- 私有表包含 user_id，复合唯一键与外键覆盖归属，仓储查询必须带 user_id；共享市场数据与个人分析严格分表。
- better-sqlite3 同步 SQL 改为 pg 异步仓储接口，事务边界在服务层；移除 withWorkspace 的解密/加载/序列化/整行写锁。
- 模型 Key 按字段加密，不把业务数据库整体加密成单个 blob。加密密钥与数据库备份独立保管。
- 大型回测审计文件放对象存储，数据库记录归属与摘要；下载必须鉴权。备份和恢复都要覆盖对象存储引用。
- 平台市场数据缓存遵守数据授权；不保留旧系统向每用户复制整份行情缓存的模式。
- 回测使用持久队列与 worker，任务有 user_id、reservation_id、稳定 request_id、心跳和失败状态。取消旧推荐 cron；市场数据采集作为共享客观行情任务，不按账号调用 AI。

### 会员账本关系

billing_customers：唯一 provider/customer 映射；orders：user_id、plan_id、price_version、interval、currency、amount_minor、status、provider_order_id、idempotency_key；订单价格快照不可随调价改变。

payment_events：provider + event_id 唯一，payload 摘要、处理状态与错误；subscriptions：平台订阅状态与已付账期；entitlement_grants：来源订单/发票唯一、起止日期与撤销记录；usage_ledger：user_id + request_id + feature 唯一，记录额度预留/消费/释放，事务锁定余额；jobs：持久任务与预留额度关联。

### 一次性切换执行步骤

1. 在隔离环境完成全量 schema 和异步仓储改写，按真实样本跑分析、聊天、标注、回测与用量测试。
2. 备份线上数据库、对象存储和旧快照密钥；仅迁入已确认归属的账号。用户本地 data/ 仍不自动上传。
3. 正式切换窗口统一暂停写入，终止或排空现有分析任务；解密已存在的账号快照，导入原生表，保留 ID、归属和时间戳。
4. 校验表行数、内容摘要、主外键、账户隔离、历史对话 Markdown、图表标注、回测回放；多用户合并共享行情以数据源+标的+周期+复权+时间戳去重。
5. 一次切换应用读写到 Postgres，恢复写入；不让部分账号继续走快照路径。应用代码可在开发中逐模块完成，但发布切换是一次性全量。
6. 回滚必须冻结写入，并把切换后的新数据通过变更日志/反向转换重放后恢复旧系统；仅回指旧快照会丢数据，禁止这样回滚。正式切换前完成全量回滚演练。旧快照仅离线保留用于灾备，绝不继续接生产写入。

验收标准：生产请求不加载 SQLite、无整用户快照 I/O、所有私有查询均隔离、跨实例并发无覆盖、备份恢复和切换后回滚能保存新增数据。

## 市场功能替代扫描与推荐

删除目标产品中的“荐股”“观察/下手”“自动扫描”入口、推荐历史、推荐生成 API、jobs/recommend、推荐 cron 和相关邮件触发。历史原始数据可离线归档，删除 UI 不等于未经确认销毁旧记录。README、设置、环境变量、共享类型及测试同步清理。

新增“市场”导航，所有套餐均可浏览。以用户主动筛选为核心：涨幅、跌幅、成交额/成交活跃、异常放量。这里的“瞩目”由可解释的行情指标定义，不伪装成人气、机构关注或 AI 推荐。

- 默认先支持数据源已授权且覆盖的 A 股/美股，市场和交易时段分开统计，港股等只在验证覆盖后显示。
- 每行包含代码、名称、价格、涨跌幅、成交额或成交量、更新时间；跨市场不直接比较未统一币种的成交额。
- 异常放量默认当日完整成交量 / 前 20 个完整交易日平均量；盘中若无同时间基准，明确标记口径或不显示排名。
- 支持市场筛选、搜索、排序、分页；点击打开该股票图表，可主动加入自选或发起单标的 AI 分析。
- 数据延迟、盘前/盘后、休市、停牌、缺失和过期要明确展示。只拥有日线时标记“最近交易日”，不能显示“实时热门”。
- 热门榜单必须从覆盖明确的股票池和统一时点数据构建，不使用“最近被本服务访问的股票”冒充全市场。
- 待建设接口：GET /api/market/overview、GET /api/market/movers（market/sort/page/asOf）；服务端过滤白名单字段并返回覆盖范围、来源和更新时间。共享缓存，不使用每用户 LLM 扫描。
- Free/Pro/Research 均可浏览完整基础市场列表；付费价值集中于单标的 AI 深度、回测额度与审计，不通过标注数量或“买卖名单”收费。

验收：无推荐/扫描入口、无后台推荐任务；市场列表有数据口径与过期提示；排序/分页稳定；选股后图表与分析上下文一致。

## 支付链路

### 国内：先预付会员月包/年包

推荐桌面微信 Native 扫码、支付宝电脑网站支付。手机访问需要微信 H5/JSAPI 与支付宝手机网站支付等相应产品开通；Native 二维码不是同机手机支付替代方案。首期可明确桌面支付范围，手机展示“请在电脑端购买”，不呈现无法使用的二维码。

1. 已登录用户选套餐；后端从价格白名单取金额/币种/周期，创建 pending 订单，重复点击复用有效待付款订单。
2. 服务端请求支付平台，返回二维码或收银台跳转地址，前端显示金额、有效期、是否续订、订单号。
3. 用户付款。浏览器返回只展示“确认中”，不能因此授予权益。
4. webhook 先验证平台签名及时间、微信资源解密，再核对商户/app ID、订单、币种、金额与成功状态。
5. 在同一 Postgres 事务里去重事件、锁订单、将订单标为 paid、写唯一权益授予记录。事务失败返回失败以重试，不提前确认已完成。
6. 页面仅查询当前用户订单。漏通知通过平台查单与定期对账补偿，查单同样走幂等履约逻辑。
7. 订单超时关闭；迟到的真实支付仍需查单确认并履约或进入退款处理，不能丢掉资金记录。

国内续费同档从 max(当前到期,付款时间) 延长，月/年按日历周期。首版不同档位变更安排在当前权益结束生效，不做未经明确展示的折抵扣款。海外同样首版到期换档；同档续订由平台处理。已有国内权益时阻止额外信用卡订阅，已有卡订阅时阻止重叠月包；切换渠道需先安排取消自动续订，到期后启用新渠道，避免双扣。

账号级购买互斥必须覆盖待付款：创建国内订单或卡 Checkout 前锁定账号的 billing customer 行，只允许一个有效购买意图；重复提交复用同一意图，切渠道先关闭或确认原意图失效。若极端竞态仍导致两笔真实付款，保留完整资金流水，后到的冲突款进入人工退款队列，不授予重叠权益，也不静默吞单。

### 海外：信用卡周期订阅

有合格商户后评估 Stripe Checkout + Billing + Customer Portal。首次购买及续费以已支付发票和有效订阅状态授予对应账期，不能凭 subscription.created 或 Checkout redirect 直接开会员。验证 webhook 原始请求体签名；对 customer.subscription.*、invoice.paid、invoice.payment_failed、退款和争议事件处理；乱序事件按平台当前对象状态核验，并以发票唯一 ID 防止重复延长。

取消自动续订：保留已付账期；到期降级。失败续费：在旧已付账期结束后停止新付费任务，保留历史只读和原始数据导出，展示更新卡信息入口。删除订阅/退款/争议需更新权益并留审计，不删除用户分析数据。

退款首版由后台人工审核后调用原支付渠道；成功通知后撤销该订单/账期对应的权益，不影响后续独立购买。部分退款先进入人工核对，不根据比例自动猜测剩余权益；用户可看申请/处理中/成功/失败。具体退费政策在开售前明确展示并与商户要求匹配。

### 服务端授权与待建设接口

- `GET /api/billing/catalog` 返回版本化套餐及已启用支付渠道；未配置渠道不可点击购买。
- `GET /api/billing/me` 返回当前套餐、余额、到期、续订方式、可执行操作。
- `POST /api/billing/checkout` 输入 plan/interval/provider/idempotency_key；不接受客户端金额、user_id 或权益日期。
- `GET /api/billing/orders/:id` 强制订单归属；`POST /api/billing/portal` 从当前账号映射创建门户会话。
- `POST /api/billing/webhooks/{wechat,alipay,stripe}` 免浏览器 session/Origin 限制，但必须使用各平台签名校验。当前 cloud handler 默认要求登录和 Origin，需在这里增加精确路由分支，不能把整个 /billing 暴露为免鉴权。
- 鉴权中间件覆盖 chat、backtests/run、wyckoff-ai-backtests/run、market 共享数据访问、收藏写入及后台任务；标注仅校验归属与请求边界，不设套餐总量限制；服务端执行配额限制，前端只负责解释升级原因。

## 商户与资源开通指南

现在没有商户，因此先确定经营主体与结算账户所在地区；提供真实业务说明与产品截图，明确 AI 股票研究、市场浏览和回测内容，向渠道确认是否受理。不能只把有金融研究功能的产品描述为普通笔记工具。

1. **通用资料**：主体证照/身份材料、负责人和受益人资料（按平台要求）、匹配的结算银行账户、客服信息、域名、产品介绍、价格、用户协议、隐私与退款政策。需要哪些资料以实际签约产品审核为准，不在聊天提交密钥或证件。
2. **微信支付**：通过官方商户平台申请；确认主体和 AppID 类型符合 Native 准入，完成商户号/AppID 关联与产品开通。服务器配置 mchid、appid、商户 API 私钥及证书序列号、API v3 key、微信支付公钥 ID/公钥（或平台证书）与 HTTPS notify_url。密钥进入部署密钥库。先完成官方联调，再按渠道许可做小额真实付款/查单/退款验证。
3. **支付宝**：在开放平台创建应用，按场景签约电脑网站支付（扫码则另确认当面付权限）；选择 RSA2 密钥或证书模式，保存 APPID、应用私钥、支付宝公钥或证书配置，设置 notify_url 和 return_url。沙箱先联调，生产应用/网关/签约权限单独校验，真实小额付款与退款后再开售。
4. **海外信用卡**：Stripe 支持地区列表包含香港、日本等，当前大陆不在标准 Payments 支持地区列表。根据真实主体选择合规可开通渠道；不能仅因人在日本或有海外卡就认为有资格。账户审核通过后创建 Pro/Research 月/年价格（USD 为独立价格），配置 Checkout、Customer Portal、事件 endpoint。先测试模式覆盖 3DS、支付失败、续费、取消、重复/乱序回调与退款；生产 secret、price IDs 与 webhook secret 分离存放。
5. **Google**：Google Cloud 创建 OAuth Web 应用，配置同意屏幕/测试用户/回调域名；仅身份基本 scope。Client ID、Secret 和正式 base URL 交给服务端环境配置；验收新注册、已有账号关联、失败返回、退出、过期会话。
6. **数据库/域名**：创建正式与预发布独立数据库；最小权限账号、TLS/连接池、自动备份与恢复演练。正式域名证书生效后固定 OAuth 和支付回调地址；不把临时预览 URL 当生产回调。
