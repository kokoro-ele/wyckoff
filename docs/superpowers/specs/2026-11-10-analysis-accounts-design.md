# 分析工作台：界面精简、登录与邀请额度

状态：待用户确认充值规则与实施设计。2026-11-10。

## 目标与界面

保留当前 Looseleaf 手绘主题。顶部仅显示自选、搜索、充值、设置、分析五个入口；分析切换研究面板，实际执行分析使用研究面板的按钮。图表标题区移除搜索、主题选择和回测入口，只保留收藏操作；周期、复权、指标、绘图工具继续可用。主题选择和纸面动效放入设置。删除用户配置 API 的界面与写接口，用户不能覆盖平台模型地址或密钥。

移除回测、扫描和推荐记录的前端入口、调用、服务路由和定时调度（含 Vercel cron）。旧数据库记录保留作兼容，不执行破坏性删除。自选中移除扫描生成分组及推荐收益字段的展示，保留用户主动收藏的标的。

## 实现方式

推荐复用现有 Better Auth 与 PostgreSQL 账号基础，在同一数据库增加邀请与额度账本。可替代方案是迁移到另一套托管认证，但需要迁移账号且并不能省去额度与邀请实现，因此不采用。此次不重写行情和标注的存储架构；当前每用户工作区由 PostgreSQL 保存加密 SQLite 快照。

## 登录与邮箱

Google OAuth 与邮箱密码注册并行；邮箱注册必须完成六位验证码验证后进入工作区。验证码短期有效、单次使用、限制尝试与重发频率，复用 Better Auth emailOTP 插件。支持验证码重发、密码找回与退出登录。Google 返回可信的已验证邮箱才可获得分析权益。未验证或未登录用户不能调用分析、访问私人数据或领取额度。

运行环境必须提供数据库、认证密钥、固定站点 URL、Google OAuth 客户端、SMTP 发件配置及平台模型凭据。缺少配置时展示明确不可用状态，不能伪造发送成功或绕过验证。测试邮件只发给用户明确指定的测试邮箱。

## 赠送与邀请

- 新用户验证成功后一次性发放 3 次，不按月刷新；同一账号多次登录、重复回调不重复发放。
- 每个账号生成不可预测且唯一的邀请码，提供复制代码与带码注册链接。
- 新用户可在注册时填写邀请码，Google 流程也保留邀请码；邀请关系由服务端校验并绑定。
- 被邀请用户完成验证后，邀请人获得 3 次；新用户同时领取自己的首次 3 次。
- 每个新用户只能绑定一个邀请人；禁止自邀，已有账号不能补领新用户邀请奖励；事务及唯一约束防并发重领。
- 页面展示剩余次数、邀请码与成功邀请数，不暴露受邀用户邮箱。

## 分析扣次

每次用户主动提交的 AI 分析／追问算 1 次。先原子预留、成功转消费、服务端失败返还；重复请求和并发不能透支。所有分析路径服务端强制检查，不依赖前端隐藏按钮或可关闭的计费开关。查看历史分析、图表和手动标注不扣次。模型连接只使用运营方环境配置。

## 验证与交付

关键测试覆盖：未验证账号拒绝访问、验证码错误/过期/重放/限流、新用户礼重复回调、无效邀请码/自邀/重复邀请、并发领取与扣次、失败返还、跨账号隔离、已删除功能路由不可调用。运行类型检查、测试、lint、生产构建，浏览器检查五按钮、设置、注册与额度状态。实际 Google 登录与验证码收信依赖真实服务配置，缺少时明确标注未联调；不把 mock 测试当作真实接通。

## 可实施性复核补充

- 取消开发前端与无 DATABASE_URL 后端的匿名分析绕过；默认要求认证和额度，缺失配置拒绝分析。既有本地数据不自动归属给注册用户。
- Google 跳转前创建服务端签发、绑定浏览器、一次性的邀请上下文；验证回调不能靠客户端任意补绑邀请码。新用户礼与邀请奖励使用不同唯一事件键，事务内落账。
- 成功消费须有可恢复的分析结果已经保存。每次请求记录预留、结果保存与消费状态，并支持中断恢复；失败按原额度来源返还，断线/重复请求不再次扣款。若保留套餐，先用当月套餐额度，再使用永久赠送次数。
